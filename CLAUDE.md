# NFL Bet Engine — orientation for Claude

Read this before doing anything else in this repo. It captures the
project state, the load-bearing decisions, and the bugs you'll silently
re-introduce if you don't know about them.

## What this is

A free-data, leakage-safe NFL game prediction system. Spread / ML /
total / Wong-teaser markets. Walk-forward backtested 2014–2025 on the
nflverse warehouse plus Open-Meteo weather. Built to match the
[MLB Bet Engine](https://github.com/ShamgarBN/mlb-bet-engine)
architecture and rigor, NFL-specific everywhere.

Goal: **above-market accuracy for the 2026/2027 season**. ML engine-bet
accuracy and Wong teasers are the markets we've already proven
above-market on; ATS top-10% works on the most-confident edge picks
but the full ATS slate is still ~50%.

## Where things live

- `src/nfl_model/data/warehouse.py` — DuckDB schema + query/upsert
- `src/nfl_model/data/sources/` — per-source ingestors (nflverse, weather, venues, aggregations)
- `src/nfl_model/data/pipeline.py` — `ensure_venues()`, `pull_season(year)`
- `src/nfl_model/features/` — one module per feature group, all import `from nfl_model.data.warehouse import query`
- `src/nfl_model/features/_rolling.py` — leakage-safe rolling helper (uses `shift(1)`; **never** add a feature without it)
- `src/nfl_model/features/assemble.py` — top-level feature joiner; **register new feature modules in the loop here**
- `src/nfl_model/model/` — scores (Stage A), simulate (Stage B), spread_direct + totals (binary heads), ensemble blend, calibrators
- `src/nfl_model/backtest/walkforward.py` — re-fits per target season on prior seasons only; writes calibrators from OOF
- `src/nfl_model/backtest/ablate.py` — drop-one-group ablation; **register new feature groups in `FEATURE_GROUPS` here**
- `src/nfl_model/predict/weekly.py` — live weekly prediction pipeline used by CLI + app
- `src/nfl_model/app/` — FastAPI + HTMX desktop app

## Critical gotchas — DO NOT silently regress these

### 1. nflverse `spread_line` has the OPPOSITE sign convention from sportsbooks

In nflverse, `spread_line` is **"points the home team is favoured by"**
(positive when home is the favorite). The rest of this codebase — the
simulator, backtest cover math, the app's pick formatting — uses the
standard sportsbook convention where a *negative* spread means the
home team is laying points (KC -3.5).

**`pull_odds_from_schedules` in `data/sources/nflverse.py` negates this
at ingestion time.** Don't remove that negation. The regression test
`tests/test_odds_sign_convention.py` will catch the bug if you do —
but if you change tests too, you'll see your backtest ATS leap to
80%+ which looks like success but is actually picks-graded-backwards.

### 2. Picks are edge-vs-market, not raw `|p − 0.5|`

`|p_home_cover − 0.5|` rewards picks where the model is most confident
the picked side covers — but at sharp markets those tend to be heavy
favorites who don't cover any better than 50%. Top-3% by raw
conviction came in at **47% ATS** (worse than coin flip).

Picks are now: `expected_cover_margin = expected_margin + posted_spread`;
pick home when positive, away when negative; conviction is the magnitude
in points. Same shape for totals. See `walkforward.py` around the
"Spread conviction" comment and `predict/weekly.py`.

### 3. LightGBM needs libomp; arm64 macs without `/opt/homebrew/libomp/`

Per-machine fix in `.venv/lib/python3.13/site-packages/lightgbm/lib/`:
the dylib's `LC_RPATH` must include the sklearn-shipped libomp. We
patched this once with:

```bash
install_name_tool -add_rpath \
  .venv/lib/python3.13/site-packages/sklearn/.dylibs \
  .venv/lib/python3.13/site-packages/lightgbm/lib/lib_lightgbm.dylib
```

If `uv sync` re-extracts lightgbm, redo this. There's no test for it
because the test of "does it work" is "import lightgbm" not failing.

### 4. Calibrators are fit from `walkforward.py`, not `model/calibrate.py`

`fit_all_calibrators()` is intentionally a no-op stub. Real calibrator
fitting happens from the OOF picks collected during a walk-forward
backtest run, by `_fit_and_save_calibrators` at the end of
`backtest/walkforward.py`. If you change the picks logic, the
calibrators need to be regenerated by running a backtest.

### 5. Feature spec is locked at train time; inference must match exactly

`model/feature_matrix.py:FeatureSpec` captures the exact column order
and per-column medians at fit time. Adding a feature mid-session that
appears in inference rows but not the spec → it's silently dropped.
Adding one that's in the spec but missing in inference → median fill.
Re-train any time you add a feature group.

## Adding a feature group — checklist

1. Create `src/nfl_model/features/<name>.py` with `def build(games: pd.DataFrame) -> pd.DataFrame:` returning a DataFrame keyed by `game_id`. All rolling aggregates must `shift(1)` first.
2. Import + register the module in the loop in `features/assemble.py`.
3. Add the column prefix(es) to `FEATURE_GROUPS` in `backtest/ablate.py` so ablation covers it.
4. Run `uv run pytest` (catches import/syntax errors).
5. Run `uv run nfl-model backtest --start 2023 --end 2024` to verify the feature flows through end-to-end without breaking.
6. Re-train production models so live predictions pick up the new feature: `uv run nfl-model train --through-season 2025 --train-start 2014`.
